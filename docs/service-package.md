# Service Package - ai-security-redteam-lab

This package defines the most practical service shape for this repository. It is public-safe: no price promises, financial projections, or buyer-specific contract assumptions are published here.

## Buyer and Wedge

- **Service lane:** AI security red-team workflow
- **Primary buyer:** Security teams and AI product teams shipping model-backed features
- **Front-door offer:** AI red-team workshop
- **Service outcome:** Run scoped prompt-injection and model-risk exercises without overclaiming security coverage.

## Build and Polish Priorities

- Clarify legal and data boundaries
- Improve remediation checklist and report language
- Separate public fixtures from private customer prompts

## Buyer-Ready Deliverables

- Threat model review
- Prompt-injection exercise
- Remediation report

## Activation Path

1. Use the public demo, README, screenshots, and tests to establish proof.
2. Confirm the buyer workflow, data boundary, owner, and acceptance criteria.
3. Build only the smallest workflow needed to prove the service outcome.
4. Add cloud resources, accounts, storage, or paid integrations only after the workflow boundary is approved.

## Margin and Risk Controls

- Keep engagements fixture-led and require explicit approval before private prompts are tested.
- Keep the first service scope narrow, repeatable, and evidence-led.
- Keep private financial planning outside the public repository.
- Keep logs, analytics, and reports free of private payloads unless explicit approval exists.

## Portfolio Signal

The portfolio should present this repository as **AI red-team workshop** under the **AI security red-team workflow** lane, with proof links routed to the live demo or repository evidence.
